clinical-workflow-lab

A referral moves through eligibility, scheduling and notification as a saga. It retries transient failures, undoes earlier steps on a permanent one, and hands steps with no API to a work-item queue. Python stdlib only, synthetic data only.

Decisions and trade-offs

All design-only: this lab was never run in production.

ChoseOverWhyCostsFlip when
Outbox in the same database transactionPublish to a broker after commitNo window where state changes but the event is lost.Needs a poller; delivery is at-least-once, so handlers must be idempotent.Throughput outgrows one database. Move to a broker with a relay.
Orchestrated sagaChoreography by eventsOne place shows where a referral is stuck and what to undo.The orchestrator knows every step and is a coupling point.Steps are owned by separate teams that need independent release.
Work-item queue with leasesBot writes directly to the databaseThe bot gets one narrow, signed surface and a crashed bot loses its claim in 60 s.One more state machine to test.The payer offers an API. Delete the manual step.
HMAC with timestampOAuth2 client credentialsNothing to run for a lab, still stops tamper and replay.Shared secret rotation is manual.Any real caller. Use OAuth2 and mTLS.
SQLitePostgres and SQSClone and run in seconds.Single writer; the lock serializes everything.Always, for anything beyond a demo. Terraform shows the SQS side.

Limits

Synthetic data. No real EHR, Epic, Notable or UiPath integration. Not a HIPAA compliance claim: encryption at rest, access control, BAAs and retention are deployment work this lab does not do. Slot and payer services are in-memory stand-ins.
